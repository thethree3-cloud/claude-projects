# Case configurator

A visual configurator for the aluminum equipment cases the shop builds:
pick dimensions, material/finish, and style options (handles, corner
bumpers, foam interior, welded mounting flanges, reinforced opening,
19" rack rails) and get back a scaled diagram plus an instant price
estimate.

Started from a real reference used to sell a customer on what a custom
case could look like — this strips the fixed dimensions out of that
concept into a reusable tool a salesperson (or a customer) can drive
themselves.

## Why a drawn diagram instead of an AI-generated photo

The picture is drawn to scale from the actual numbers (matplotlib), not
generated by an image model. That means:

- It's always dimensionally correct — a 30x30x18 case always looks like
  a 30x30x18 case, and flanges/holes/rails are placed proportionally.
- It's instant and free per configuration — no per-render API cost or
  latency.
- It won't hallucinate a hole pattern or a handle that isn't there.

The tradeoff is that it looks like a labeled spec sheet, not a product
photo. If a more marketing-ready image is wanted later, this is the
natural place to swap in an image-generation call (see below).

## Files

| File | What it does |
| --- | --- |
| `pricing.py` | `CaseSpec` (the configuration) and `compute_quote()` — material cost is physics-based (surface area x thickness x aluminum density x $/lb, so thickness genuinely drives cost), labor is hours-based (setup + area + `num_draws`, the number of forming/bend operations, x shop rate), plus finish upcharge and flat/per-unit option costs, then a markup percentage. All dollar figures live in the `PRICING` dict and are grounded in 2026 market research (sources in the module docstring) but are **still placeholders**, not actual Zerocases costs — see the docstring for which figures are well-sourced vs. judgment calls (rack rails and handle hardware specifically). |
| `diagram.py` | `draw_case()` — draws front/side/top-down views to scale from a `CaseSpec`, including reinforced-opening border, corner bumpers, welded flanges with bolt holes, a handle icon, and rack rails, matching the style of the original reference sheet. |
| `valan_catalog.py` | **Real** dimension/thickness/hardware data for all 52 case sizes, transcribed from a customer-provided PDF (Zero Manufacturing's VAL-AN Series catalog: width, length, material gauge, the case-height range each size allows, and the handle/latch/hinge counts used in that size's own worked ordering example). |
| `valan_pricing.py` | `compute_valan_price()` — the real catalog's hardware (latches, hinges, an automatic/manual pressure-relief valve, an instrument-case adder for the extra feet that case type always carries) layered on top of `pricing.py`'s already-sourced material/labor costs. Latch/hinge/valve/case-type dollar figures are placeholders (sources and gaps noted in the docstring) — real invoice numbers would slot in here directly. |
| `generate_quote_history.py` | Builds a ~2,000-row "historical quote" database (`data/quote_history.db`, gitignored): real dimensions/thickness/hardware from `valan_catalog.py`, prices computed via `valan_pricing.py` plus random noise so they scatter like real quotes would, while still trending reliably more expensive for bigger/thicker/more-complex cases (verified: smallest case AA averages ~$230, largest MB averages ~$1,006). Each row also varies case type (combination/transit/instrument), valve (automatic/manual), and finish. Run it once with `python generate_quote_history.py` (fixed random seed, reproducible) to (re)build the database. |
| `quote_lookup.py` | Given a configuration, finds similar rows in the quote history (within a dimension/draw-count tolerance) and reports an average price plus a confidence score based on how many nearby matches exist — the "historical predictive quoting" idea, now feeding this configurator instead of standing alone. |
| `streamlit_app.py` | The configurator UI: sidebar inputs drive a live diagram, a line-item formula quote, and a "similar past quotes" panel from the history database. |
| `test_pricing.py` | Unit tests for the surface area / volume math and the quote formula (14 tests). |
| `test_quote_history.py` | Unit tests for the catalog-driven data generator and the similarity/confidence lookup (10 tests). |

Note: `pricing.py`'s two material thickness classes (.063"/.090") and its
aluminum density figure (0.098 lb/in3) also come from the VAL-AN catalog —
it uses deep-drawn 6061 aluminum in exactly those two gauges, and its own
weight formula implies that density directly (more reliable than a generic
alloy lookup). See `pricing.py`'s docstring for the full source list.

## Running it

```bash
python generate_quote_history.py   # one-time: builds data/quote_history.db
streamlit run streamlit_app.py
```

## Known limitations / next steps

- **Pricing is a research-grounded formula, not real shop costs.** Before
  this quotes a real customer, replace the constants in `PRICING` (and
  the two weakest-sourced figures — rack rails and handles — with real
  invoice numbers if available).
- **The quote-history prices are still fake**, even though the
  dimensions/thickness/hardware counts they're computed from are now real
  (the VAL-AN catalog). If Zerocases' actual past quotes become available,
  swap them in for the synthetic prices in `generate_quote_history.py` —
  the dimension side of the pipeline is already real.
- **This VAL-AN data models a specific existing product line** (transit/
  instrument/combination cases with latches, hinges, a pressure-relief
  valve, an optional inner lid) which doesn't perfectly match the
  configurator's own option set above (handles, bumpers, foam, rack rails,
  mounting flanges, reinforced opening — closer to the original one-off
  custom enclosure this tool started from). The two are kept as separate
  cost models (`pricing.py` vs. `valan_pricing.py`) on purpose rather than
  forcing one option set onto both; unifying them would be a real next
  step if this configurator settles on modeling the VAL-AN line
  specifically.
- **The diagram is a labeled schematic, not a rendered photo.** If a
  more sales-ready image is wanted, the natural next step is an
  AI image-generation call built from the same `CaseSpec` (prompt
  template driven by width/height/depth/color/options) as an
  alternative render mode — kept out of v1 because it costs money per
  render and won't stay dimensionally consistent between renders.
- No persistence yet for a customer's chosen configuration — each
  session is a fresh quote. A "save/export this quote as a PDF" step
  would be the natural next slice if this moves from experiment to
  something reps actually use.
